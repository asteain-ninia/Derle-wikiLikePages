出界百科の使い方

記事を書いて公開するまでの手順と、困ったときの見どころ。仕組みの図は Derle-wikiLikePages 移行後、移行の経緯は 移行の記録 にあります。

ふだんの流れ記事を公開する・取り下げる更新履歴に載るもの・載らないもの古い版出す前に手元で確かめる数値と計算機デプロイの様子を見る・手で動かすうまくいかないとき2 台の PC で使うとき新しい PC で始めるとき鍵とトークン控え

記事を公開する・取り下げる

したいことやること
記事を公開する記事の先頭の frontmatter に 公開: true を書く
公開をやめる公開: true を消す (または 公開: false にする)。次のデプロイで記事も古い版のページも消える
画像を出す公開する記事の中に画像のファイル名を書く (![[地図.png]] など)。どの公開記事にも名前が無い画像は出ない
記事の名前を変えるObsidian でファイル名を変える。履歴は引き継がれるが、記事の URL は変わる (古い URL からの転送は無い)

frontmatter は キー: 値 と - 項目 の単純な形だけを読む。読めない形の記事は、公開: true と書いてあっても出さない。

更新履歴に載るもの・載らないもの

  • 保管庫でその記事に触れたコミットは、全部その記事の更新履歴に載る。 文言がそのまま編集要約になる。公開する前のコミットも載る。
  • 載せたくないコミットは、文言を chore: で始める。 公開: true を付けるだけのコミットや、機械的な一括の整理に使う。例: chore: 公開する記事に 公開: true を付ける
  • 「作成」日は最初のコミットの日、「更新」日は履歴に載るコミットのうち最新の日。 chore: のコミットでは更新日は動かない。
  • 1 つのコミットで複数の記事を変えると、同じ文言がそれぞれの記事の履歴に載る。

古い版

  • 履歴の文言を押すと、その時点の版のページが開く。 場所は article/<記事>/rev/<版>/。上部に「○年○月○日時点の古い版です」と最新の版へのリンクが出る。
  • 公開する前の版も読める。
  • 古い版のページは検索に載せない。 noindex を付け、sitemap にも入れていない。
  • 昔の版にしか使われていない画像は表示されない。

出す前に手元で確かめる

このリポジトリで次を実行し、http://localhost:4173 を開く。

npm run dev
  • 保管庫を見張っていて、記事を保存するたびに作り直してブラウザを再読み込みする。 コミットしていない内容もそのまま見える。
  • 保管庫の場所は、リポジトリ直下の local.config.json に書く。 PC ごとに置き、git には入らない。中身は { "vaultPath": "C:/Users/…/OneDrive/ドキュメント/出界百科" }
  • 手元の content/ と .generated/ は自動で作られる生成物。 編集もコミットもしない。

数値と計算機 (出界の織機)

  • {{織機|量|単位|有効数字}} と書くと、ビルドのときに計算値に置き換わる。
  • {{計算機|単位}} や {{計算機|時刻}} の行は、読者が数字を入れられる計算機になる。
  • 量と単位の名前は loom.md にある。

デプロイの様子を見る・手で動かす

# 最近のデプロイ
gh run list -R asteain-ninia/Derle-wikiLikePages --limit 3

# 失敗したときの記録
gh run view <番号> -R asteain-ninia/Derle-wikiLikePages --log-failed

# 手でデプロイする
gh workflow run deploy-pages.yml -R asteain-ninia/Derle-wikiLikePages

デプロイが始まるきっかけは 3 つある。保管庫の push、このリポジトリの main への push (コードを変えたとき)、手での実行。

うまくいかないとき

起きたこと見るところ
push したのに記事が出ない記事に 公開: true があるか。gh run list でデプロイが成功しているか。成功していれば、ブラウザの再読み込みを試す
push してもデプロイが始まらないgh run list -R asteain-ninia/derle-vault --limit 1 で「Notify site」が動いたか。動いていて警告や失敗が出ていれば、トークン (下の表) を作り直す
デプロイが「Checkout vault」で失敗する保管庫を読む鍵 (下の表) が消えたか、保管庫のリポジトリ名が変わった
デプロイが「Run tests」や「Build static site」で失敗するコードか原稿の問題。--log-failed の記録で、止まった場所とエラーの文言を見る
履歴に出したくないコミットが出た次から chore: で始める。push 済みのコミットの文言を直すのは履歴の書き換えになるので、どうしても消したいときだけ
画像が出ない公開している記事の本文かインフォボックスに、その画像のファイル名が書かれているか

2 台の PC で使うとき

  • 2 台で同時に保管庫の git を使わない。 保管庫は OneDrive で同期され、.git も一緒に同期される。もう 1 台で作業する前に、OneDrive の同期が終わるのを待つ。
  • 競合コピーは消して構わない。 2 台で Obsidian を開いたままにすると、OneDrive が .obsidian/workspace-PC名-番号.json を作ることがある。.obsidian/workspace*.json は git に入れていない。
  • このリポジトリは PC ごとに git pull する。 local.config.json も PC ごとに置く。

新しい PC で始めるとき

  1. OneDrive の同期で保管庫「出界百科」が届くのを待ち、Obsidian で開く。
  2. このリポジトリを clone する。Node.js が要る (Actions は 24 を使っている)。追加で入れるパッケージは無い。
  3. リポジトリ直下に local.config.json を作り、保管庫の場所を書く。
  4. npm run dev で表示を確かめる。
  5. gh auth login で GitHub にログインする (push と gh のコマンドに要る)。

鍵とトークン

名前置き場所役目期限
VAULT_DEPLOY_KEYDerle-wikiLikePages の secret。対になる公開鍵は derle-vault の Deploy keys「Derle-wikiLikePages Actions (read-only)」Actions が非公開の保管庫を読む。読み取り専用なし
SITE_DISPATCH_TOKENderle-vault の secret。中身は GitHub の fine-grained トークン「derle-vault notify」保管庫の push をきっかけに、このリポジトリの Actions を起こす。届くのは Derle-wikiLikePages の Contents だけなし
  • トークンを作り直す。 GitHub の Settings → Developer settings → Personal access tokens → Fine-grained tokens で「derle-vault notify」を Regenerate し、gh secret set SITE_DISPATCH_TOKEN -R asteain-ninia/derle-vault で貼り直す。
  • 鍵を作り直す。 ssh-keygen -t ed25519 で作る。公開鍵を gh repo deploy-key add <公開鍵> -R asteain-ninia/derle-vault、秘密鍵を gh secret set VAULT_DEPLOY_KEY -R asteain-ninia/Derle-wikiLikePages < <秘密鍵> で登録し、手元のファイルを消す。
